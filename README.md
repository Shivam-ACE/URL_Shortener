# URL Shortener with Analytics

A production-style URL shortener built with **FastAPI**, **PostgreSQL**, and **Redis** — with JWT authentication, click analytics, cache-aside redirects, and rate limiting.

Built as a backend engineering project to go beyond CRUD: it demonstrates auth design, caching strategy, asynchronous event recording, and abuse protection, in a clean layered architecture.

## Features

- **Authentication** — register/login with passwords hashed using **Argon2** (via `pwdlib`) and stateless **JWT** bearer tokens (via `PyJWT`)
- **Short links** — short codes generated by **Base62-encoding the link's database ID**: unique by construction, no random generation, no collision handling
- **Fast redirects** — public `GET /{code}` endpoint returning `302` (never `301`, so every visit still reaches the server and deactivated links stop working)
- **Redis cache-aside** — the redirect checks Redis first and only queries PostgreSQL on a miss, then populates the cache (1-hour TTL)
- **Click analytics** — every redirect records IP address, user-agent, referer, and timestamp **asynchronously via FastAPI `BackgroundTasks`**, so tracking never slows the redirect down
- **Per-link stats** — total clicks and full click history per link, visible to the link's owner only
- **Rate limiting** — link creation limited to **10 requests/minute per user** (Redis fixed-window counter), returning `429` with a `Retry-After` header
- **Link management** — list your links, and deactivate a link (which also evicts it from the cache immediately)
- **Graceful degradation** — if Redis is unavailable, redirects fall back to PostgreSQL and the rate limiter fails open; the app keeps working

| Layer | Technology |

## Architecture

```
app/
├── main.py               # app creation, router wiring
├── api/                  # HTTP layer: routers + dependencies
│   ├── auth.py           #   register, login, /me
│   ├── links.py          #   create, list, stats, deactivate
│   ├── redirect.py       #   public GET /{code}
│   └── deps.py           #   get_current_user (HTTPBearer), rate_limit
├── core/                 # framework-free building blocks
│   ├── config.py         #   settings from environment
│   ├── security.py       #   password hashing, JWT create/verify helpers
│   ├── base62.py         #   ID <-> short-code encoding
│   └── cache.py          #   Redis client + cache helpers
├── db/                   # engine, session factory, declarative base
├── models/               # SQLAlchemy models: User, Link, Click
├── schemas/              # Pydantic request/response models
└── services/             # business logic: user, link, click services
```

Routers stay thin, services own the database work, and `core` never imports FastAPI — each layer only depends on the ones below it.

## API Endpoints

| Method | Path | Auth | Description |
|---|---|---|---|
| GET | `/health` | — | Health check |
| POST | `/auth/register` | — | Create an account (`201`) |
| POST | `/auth/login` | — | Login, returns a JWT |
| GET | `/auth/me` | Bearer | Current user's profile |
| POST | `/links/` | Bearer | Create a short link (rate-limited, `201`) |
| GET | `/links/` | Bearer | List my links, newest first |
| GET | `/links/{id}/stats` | Bearer | Click stats for my link (owner only) |
| PATCH | `/links/{id}/deactivate` | Bearer | Deactivate my link + evict its cache entry |
| GET | `/{code}` | — | Redirect to the original URL (`302` / `404`) |

Interactive docs are available at `/docs` on a running instance.

## Key Design Decisions

- **Base62 of the database ID** — the short code is derived from the auto-increment primary key, so uniqueness is guaranteed by the database itself. The row is inserted with `flush()` to obtain the ID, the code is generated, and both are persisted in a **single transaction**.
- **The cache stores a JSON payload, not just the URL** — `{ "id": ..., "original_url": ... }`. On a cache hit there is no database row, but click recording still needs the link's ID; caching both keeps analytics working on every hit. Misses (404s) are deliberately **not** cached, so a code that doesn't exist yet can't be poisoned.
- **Click recording uses its own DB session** — background tasks run after the response is sent, when the request's session is already closed, so the recording task opens and closes its own session.
- **Ownership failures return 404, not 403** — stats and deactivation don't confirm to other users that a link exists. The owner of a link is always taken from the JWT, never from the request body.
- **Fixed-window rate limiting with `INCR` + `EXPIRE NX`** — both commands run in one Redis pipeline, and the expiry is set only if none exists, anchoring the window to the first request instead of letting repeated calls extend it forever.

## Run Locally

**Prerequisites:** Python 3.13, a PostgreSQL database, and a Redis instance (local or a free [Upstash](https://upstash.com) database).

```bash
git clone https://github.com/Shivam-ACE/URL_Shortener.git
cd URL_Shortener
python -m venv venv
venv\Scripts\activate        # Windows; use source venv/bin/activate on Linux/macOS
pip install -r requirements.txt
```

Create a `.env` file (see `.env.example`):

```env
DATABASE_URL=postgresql://user:password@localhost:5432/url_shortener
SECRET_KEY=your-secret-key
ALGORITHM=HS256
ACCESS_TOKEN_EXPIRE_MINUTES=5
REDIS_URL=rediss://your-upstash-url
```

Start the server:

```bash
uvicorn app.main:app --reload
```

Open http://127.0.0.1:8000/docs — register a user, login, authorize with the returned token, create a link, and open `http://127.0.0.1:8000/{short_code}` in a browser.
